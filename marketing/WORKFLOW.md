# Як змінювати макет і готувати випуск

1. Знайти точний документ у DOCUMENT_CATALOG.md. Відкрити його останній PDF/прев’ю та відповідне HTML/CSS/дані. Уточнювати лише відсутній файл/ідентичність документа, а не просити повторний дозвіл на вже запитані правки.
2. Змінити тільки потрібні тексти/фото/елементи. Якщо змінюється текст за запитом власника, оновити контрольний текст для цього документа. Зберегти джерело й робочий результат окремо від базового випуску.
3. Для семи Commercial/PGP документів використовувати [source/README.md](source/README.md), [documents.json](source/documents.json), `source/tools/render.cjs` і `source/tools/finalize.py`. З кореня `source/`: `npm install`, `npx playwright install chromium`, `python -m pip install -r requirements.txt`, потім `node tools/render.cjs` і `python tools/finalize.py`. За наявності Edge встановити `GCPRO_BROWSER_CHANNEL=msedge`. Результат — `source/rebuilt/`. Це команди повторного випуску з проєкту, не твердження про новий запуск 2026-11-05.
4. Для ASP/PSP використовувати [джерельний README](source/01_Brand_System/README.md). Запускати тільки актуальні ключі: `python build.py LB5 RC5 RR5 PSP5 DF5 ERP5 SR01 SR02 SR03 SR04_1 SR05 SR06_1 NB5 AP5 PR5 INV5`. Запуск без ключів також створює старі версії — їх не пакувати. Залежності й локальні шрифти описані в джерелах.
5. Перевірити змінені сторінки: текст, обрізання, вирівнювання, кадрування, пропорції, trim/bleed, відсутність випадкових заглушок і службових кодів. Використовувати шрифти з проєкту; вбудовані subset-шрифти стороннього PDF не завжди можна повторно застосувати до нових літер. Не закривати проблему квадратними символами або заміною всього дизайну.
6. Для Fillable: звірити кількість і назви полів, канонічне AcroForm-дерево, Widget-посилання й AP appearance streams. Пробно ввести текст/обрати checkbox, зберегти й відкрити файл знову. Для Print підтвердити відсутність інтерактивних widgets. Контракти — `source/06_Release_Data/*-fields.json`.
7. Передати прев’ю. Після погодження власником сформувати окремий датований випуск зі структурою базового кіта, оновити каталог, інвентар і CURRENT_RELEASE.json. Не переписувати історичну дату/контрольні суми старого випуску.
8. Перевірити цілісність архіву та наявність тільки актуальних версій. У короткій відповіді надати результат і матеріальні обмеження. Нові програми на сайті — окреме завдання; цей процес не публікує сайт.

`03 Logos` → `GCPRO` та `Property Guardian Program`. `04 Previews` → тільки оглядові матеріали. У корені — START HERE.html, README та інвентар. Файли проєкту передавати окремо від готового кіта, коли це потрібно.
